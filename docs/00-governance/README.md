# Documentation Governance

## Documentation rules

- Documentation must describe actual intended or implemented behavior.
- Mark documents `DRAFT`, `IN REVIEW`, `APPROVED` or `SUPERSEDED`.
- Include owner, last-updated date and related decision IDs where useful.
- Approved requirements change only through a recorded change request.
- Keep one canonical document per subject; link rather than duplicate.
- Code and tests are evidence of implementation; approved specifications define intended behavior.
- If code and approved documentation diverge, record the discrepancy and resolve it.

## Suggested document header

```md
> Status: DRAFT
> Owner: Product Owner / Engineering
> Last updated: YYYY-MM-DD
> Related decisions: DEC-001
```
