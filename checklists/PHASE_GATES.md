# Phase Gates

## Gate 1 — Product approval
- [ ] Problem and target users are clear.
- [ ] MVP and non-goals are defined.
- [ ] Critical business rules are approved.
- [ ] Acceptance criteria are testable.
- [ ] Risks and assumptions are visible.

## Gate 2 — Design approval
- [ ] Navigation and core journeys reviewed.
- [ ] Screen specifications exist for MVP.
- [ ] Loading, empty, error and offline states covered.
- [ ] Accessibility and localization considered.
- [ ] Design references and tokens approved.

## Gate 3 — Architecture approval
- [ ] Stack decision documented with alternatives.
- [ ] Module boundaries and data flows defined.
- [ ] Database and API contracts reviewed.
- [ ] Security and privacy risks assessed.
- [ ] Build, test and deployment strategy defined.

## Gate 4 — Feature completion
- [ ] Acceptance criteria met.
- [ ] Implementation integrated.
- [ ] Relevant tests executed.
- [ ] Regression impact reviewed.
- [ ] Docs and inventory updated.

## Gate 5 — Release candidate
- [ ] No unresolved critical/high defects unless explicitly risk-accepted.
- [ ] Security and dependency checks reviewed.
- [ ] Performance budgets assessed.
- [ ] Backup/restore and rollback plan tested.
- [ ] Staging smoke tests passed.
- [ ] Monitoring and support ready.

## Gate 6 — Production release
- [ ] User explicitly approved this release.
- [ ] Correct artifact and environment verified.
- [ ] Release and migration plan reviewed.
- [ ] Post-deployment checks defined.
