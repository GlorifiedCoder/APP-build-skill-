# Approval Policy

## Autonomous actions
- Read files and inspect repository state.
- Draft plans, specifications and code.
- Edit files within the requested project scope.
- Run local builds, tests, lint and static analysis.
- Create local test data.
- Update documentation and task trackers.

## Explicit approval required
- Core architecture or technology changes.
- Material recurring costs or paid vendor commitments.
- Destructive data/schema operations.
- Access to or export of real user data.
- Production credentials or infrastructure changes.
- Security/privacy control changes.
- External publishing, messaging, purchases or transactions.
- Production deployment and app-store submission.

## Approval record
Record: action, reason, impact, alternatives, rollback plan, approver, timestamp and scope.
Approval for one action does not authorize unrelated future actions.
