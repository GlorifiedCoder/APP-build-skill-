# Workflow 03 — Architecture and Stack

## Steps
1. Derive architecture requirements from product and non-functional requirements.
2. Compare native Android, native iOS and cross-platform options.
3. Select technologies based on requirements, team capability, ecosystem maturity, lifecycle, cost and maintenance.
4. Define module boundaries and dependency rules.
5. Design identity, authorization, data model, API contracts and integrations.
6. Define offline/cache/sync behavior if needed.
7. Threat-model sensitive flows.
8. Define environments, observability, backup and release strategy.
9. Record alternatives and trade-offs in decision records.

## Approval gate
User approval is required before changing core technology, architecture or material recurring-cost decisions.

## Outputs
Approved architecture, stack, project structure, schema, API contract and threat model.
