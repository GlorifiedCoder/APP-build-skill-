# Workflow 04 — Implementation

## Rules
- Work in small, reviewable vertical slices.
- Implement one user outcome end-to-end: UI, domain logic, data/API and tests.
- Follow approved specs and architecture.
- Inspect existing code before editing.
- Do not rewrite unrelated modules.
- Keep changes reversible where practical.

## Per-slice cycle
1. Select a READY task.
2. Confirm acceptance criteria and dependencies.
3. Create a short implementation plan.
4. Implement code and tests.
5. Run formatter, lint, static analysis, tests and build.
6. Inspect diff and security implications.
7. Update docs, feature inventory and task tracker.
8. Report evidence and remaining gaps.

## Stop conditions
Stop and ask if requirements conflict, scope expands materially, a destructive migration is needed, or an approval-required action is reached.
