# Skill: Mobile Architecture

## When to use
Use when selecting mobile architecture, frameworks or module boundaries.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Identify target platforms, OS support, offline needs and device capabilities.
2. Compare native and cross-platform options using explicit criteria.
3. Define presentation, domain and data responsibilities.
4. Define navigation, dependency injection, state and lifecycle strategy.
5. Define persistence, synchronization and network resilience.
6. Define testability, build variants and release configuration.
7. Record trade-offs and approval-required decisions.

## Expected outputs
Approved stack proposal, architecture, module map and ADR.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
