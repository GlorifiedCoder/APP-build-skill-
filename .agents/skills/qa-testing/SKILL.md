# Skill: Qa Testing

## When to use
Use to plan, execute and report quality verification.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Map acceptance criteria to test cases.
2. Select unit, integration, contract, UI and E2E levels.
3. Include negative, boundary, permission and recovery scenarios.
4. Execute tests and record exact commands/results.
5. Reproduce and classify failures.
6. Verify fixes and run regression.
7. Never mark unexecuted tests as passed.

## Expected outputs
Test plan, executed results, defect records and evidence.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
