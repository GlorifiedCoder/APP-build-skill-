# Skill: Backend And Api Design

## When to use
Use when designing backend services, APIs or integrations.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Identify clients, actors and trust boundaries.
2. Define resource and domain boundaries.
3. Specify request/response schemas and validation.
4. Define auth, authorization, rate limits and idempotency.
5. Define pagination, errors, timeouts and retries.
6. Specify webhook verification and integration failure behavior.
7. Publish OpenAPI contract and contract tests.

## Expected outputs
API specification, OpenAPI document, integration contracts.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
