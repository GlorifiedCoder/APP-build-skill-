# Skill: Documentation Maintenance

## When to use
Use whenever implementation changes documented behavior or project structure.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Identify affected canonical documents.
2. Compare current implementation and intended behavior.
3. Update only relevant sources of truth.
4. Update links, statuses, decisions and changelog.
5. Avoid duplicating the same facts in multiple documents.
6. Flag unresolved mismatches.

## Expected outputs
Consistent, current documentation and decision history.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
