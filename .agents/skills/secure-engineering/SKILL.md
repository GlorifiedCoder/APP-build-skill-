# Skill: Secure Engineering

## When to use
Use when handling identity, permissions, sensitive data, integrations or release security.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Identify assets, actors, trust boundaries and attack surfaces.
2. Review authentication and server-side authorization.
3. Review input validation, storage, transport and secrets.
4. Review logging, analytics, backups and data retention.
5. Check dependency and platform risks.
6. Define abuse cases and mitigations.
7. Record findings by severity with evidence.
8. Escalate suspected exposure immediately.

## Expected outputs
Threat model, security requirements, audit findings and remediation plan.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
