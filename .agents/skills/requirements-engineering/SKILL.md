# Skill: Requirements Engineering

## When to use
Use when converting product intent into implementable requirements.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Read Product Vision and user journeys.
2. Write uniquely identified functional and non-functional requirements.
3. Define actors, permissions, preconditions and business rules.
4. Write observable Given/When/Then acceptance criteria.
5. Include negative, boundary, offline and recovery cases.
6. Trace requirements to features, screens, APIs and tests.
7. Flag ambiguity and request approval for material trade-offs.

## Expected outputs
PRD, feature specs, requirements traceability and acceptance criteria.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
