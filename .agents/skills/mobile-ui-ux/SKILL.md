# Skill: Mobile Ui Ux

## When to use
Use when designing mobile navigation, screens, interactions or design systems.

## Required inputs
- Relevant project brief and approved specifications.
- Current repository state and related tests.
- Applicable architecture, security and design rules.

## Workflow
1. Read approved requirements and personas.
2. Define information architecture and navigation.
3. Establish design tokens and reusable components.
4. Specify each screen, action and visual state.
5. Include accessibility, localization, dynamic type and adaptive layouts.
6. Cover loading, empty, error, offline and permission-denied states.
7. Map every interactive control to a real action and acceptance criterion.
8. Review flows for consistency and usability.

## Expected outputs
Design system, screen specs, interaction inventory and design review.

## Quality rules
- Do not invent facts, test results or approvals.
- Cite external research where used.
- Identify assumptions and unresolved risks.
- Respect `AGENTS.md` approval requirements.
- Update project documentation when the outcome changes the source of truth.
